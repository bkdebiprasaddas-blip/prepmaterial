What is ASP.NET?

Definition

ASP.NET is a Microsoft web development framework used to create dynamic, interactive and data-driven web applications. It supports server-side programming using languages such as VB.NET and C#.

Basic Architecture

Features of ASP.NET

  • Supports server-side programming.
  • Supports VB.NET and C#.
  • Provides built-in security features.
  • Supports database connectivity.
  • Provides reusable web controls.
  • Supports session and state management.
  • Allows rapid development of web applications.

Example

VB.NET
Protected Sub Page_Load(sender As Object, e As EventArgs)
    Response.Write("Welcome to ASP.NET")
End Sub
Exam Conclusion

ASP.NET provides a powerful framework for developing dynamic, secure and database-driven web applications.

Main Components of .NET Framework

A. CLR — Common Language Runtime

The CLR is the execution environment of the .NET Framework. It manages the execution of .NET programs and provides services such as:

  • Memory management
  • Exception handling
  • Security
  • Thread management
  • Garbage collection
  • Code execution

Example: When a VB.NET program runs, the CLR manages its execution.

B. FCL — Framework Class Library

The Framework Class Library (FCL) is a collection of reusable classes, interfaces and data types provided by .NET. It provides classes for:

  • File handling
  • Database connectivity
  • Web development
  • Networking
  • Collections
  • XML processing
  • Input/output operations
VB.NET
Dim file As New System.IO.FileInfo("data.txt")

Here, FileInfo is a class provided by the .NET class library.

C. CTS — Common Type System

CTS defines the standard data types and rules that all .NET-supported languages follow. For example:

CLS defines a set of common rules that .NET languages should follow so that code written in different languages can interact with each other.

CLR (Common Language Runtime)

Definition

CLR (Common Language Runtime) is the execution environment of the .NET Framework. It manages the execution of .NET programs and provides important services such as memory management, exception handling, security, thread management, and garbage collection. In simple words, CLR acts as a bridge between a .NET application and the operating system.

Components / Services of CLR

1. JIT Compiler

JIT (Just-In-Time) Compiler converts MSIL/CIL code into native machine code at runtime.

Diagram
MSIL / CIL
    │
    ▼
JIT Compiler
    │
    ▼
Machine Code

This allows the program to execute on the target computer.

2. Garbage Collector

The Garbage Collector (GC) automatically identifies objects that are no longer being used and releases their memory.

Benefit: it reduces manual memory management and helps prevent memory leaks.

3. Exception Handling

CLR provides a mechanism for handling runtime errors using exceptions.

VB.NET
Try
    Dim a As Integer = 10
    Dim b As Integer = 0
    Dim result As Integer = a \ b
Catch ex As Exception
    Console.WriteLine("Error occurred")
End Try

4. Security

CLR provides security mechanisms to control the execution of managed code and protect applications and resources.

5. Thread Management

CLR manages threads used by applications and provides support for multithreaded programming.

6. Memory Management

CLR automatically manages memory allocation and deallocation. The programmer generally does not need to manually free memory for managed objects.

7. Type Checking

CLR works with the Common Type System (CTS) to ensure that data types are used correctly and consistently.

8. Code Verification

CLR can verify managed code to help ensure that it follows the rules required for safe execution.

Functions of CLR

  1. Program execution — executes .NET applications.
  2. Memory management — allocates and manages memory.
  3. Garbage collection — removes unused objects from memory.
  4. Exception handling — handles runtime errors.
  5. Security management — provides security mechanisms.
  6. Thread management — manages application threads.
  7. Type safety — ensures proper use of data types.
  8. JIT compilation — converts MSIL/CIL into native machine code.
  9. Language interoperability — allows different .NET languages to work together.
  10. Debugging and profiling support — provides runtime support for development and diagnostics.

VB.NET Example

VB.NET
Module Program

    Sub Main()

        Dim a As Integer = 10
        Dim b As Integer = 20
        Dim sum As Integer

        sum = a + b

        Console.WriteLine("Sum = " & sum)

    End Sub

End Module
Output
Sum = 30

What CLR does here

  1. The VB.NET compiler converts the program into MSIL/CIL.
  2. CLR loads the compiled code.
  3. JIT compiler converts the required IL into machine code.
  4. CLR manages the program's memory and execution.
  5. The result is displayed on the screen.

Advantages of CLR

  • Automatic memory management
  • Garbage collection
  • Improved security
  • Structured exception handling
  • Language interoperability
  • Efficient code execution through JIT
  • Thread management
  • Type safety
  • Simplifies application development
  • Provides a managed execution environment

ADO.NET Architecture

Definition

ADO.NET (ActiveX Data Objects .NET) is a data access technology provided by the .NET Framework. It is used to connect .NET applications with databases, execute SQL commands, retrieve data, and manipulate database records. ADO.NET supports two major approaches to data access: Connected Architecture and Disconnected Architecture.

Main Components of ADO.NET

ADO.NET mainly consists of two groups of components:

A. .NET Data Provider

The Data Provider is used for direct communication between an application and a data source. Important components:

  • Connection
  • Command
  • DataReader
  • DataAdapter

B. DataSet

DataSet is used mainly in the disconnected architecture. It can store data in memory without keeping a continuous connection with the database.

5. Connected Architecture

In connected architecture, the application maintains an active connection with the database while data is being retrieved or manipulated. The connection generally remains open while commands are executed and data is read.

1. Connection

The Connection object establishes a connection between the application and the database.

VB.NET
Dim con As New SqlConnection(
    "Data Source=.;Initial Catalog=StudentDB;Integrated Security=True"
)

con.Open()

Important methods: Open() — opens the connection, Close() — closes the connection.

2. Command

The Command object is used to execute SQL statements or stored procedures.

VB.NET
Dim cmd As New SqlCommand(
    "SELECT * FROM Student", con
)

Common methods: ExecuteReader(), ExecuteScalar(), ExecuteNonQuery().

3. DataReader

DataReader provides a fast, forward-only and read-only way to retrieve data from a database.

VB.NET
Dim dr As SqlDataReader = cmd.ExecuteReader()

While dr.Read()
    Console.WriteLine(dr("Name"))
End While

Characteristics: read-only, forward-only, fast, requires an active database connection.

Connected Architecture — Working

Diagram

        ↓

Advantages of Connected Architecture

  • Provides fast data access.
  • Suitable for operations requiring continuous database communication.
  • Uses relatively less memory for large result sets.
  • DataReader provides efficient sequential reading.
  • Suitable for real-time database operations.

Disadvantages

  • Database connection must remain open.
  • Database resources remain occupied.
  • Not suitable when a connection is expensive or unreliable.
  • Multiple users can increase the number of active connections.

6. Disconnected Architecture

In disconnected architecture, the application does not need to maintain a continuous connection with the database. Data is retrieved from the database, stored in memory, and the database connection can then be closed. Main components: DataAdapter, DataSet, DataTable, DataRow, DataColumn, DataRelation.

1. DataAdapter

DataAdapter acts as a bridge between the database and the DataSet. It retrieves data from the database and fills the DataSet, and can also send changes made in the DataSet back to the database.

Important methods: Fill(), Update().

VB.NET
Dim da As New SqlDataAdapter(
    "SELECT * FROM Student", con
)

Dim ds As New DataSet()

da.Fill(ds, "Student")

2. DataSet

A DataSet is an in-memory representation of data. It can contain one or more DataTables.

DataSet does not require a permanent connection to the database while the application works with the data.

3. DataTable

A DataTable represents a table of data inside a DataSet, e.g. a Student table with ID, Name and Age columns.

4. DataRow

A DataRow represents one record/row in a DataTable.

5. DataColumn

A DataColumn represents a column or field in a DataTable.

6. DataRelation

DataRelation represents a relationship between two DataTables inside a DataSet — useful when working with related tables (for example, a Student table linked to a Course table through CourseID).

Disconnected Architecture — Working

VB.NET Example of Disconnected Architecture

VB.NET
Imports System.Data.SqlClient

Module Program

    Sub Main()

        Dim con As New SqlConnection(
            "Data Source=.;Initial Catalog=StudentDB;Integrated Security=True"
        )

        Dim da As New SqlDataAdapter(
            "SELECT * FROM Student", con
        )

        Dim ds As New DataSet()

        da.Fill(ds, "Student")

        For Each row As DataRow In ds.Tables("Student").Rows
            Console.WriteLine(row("Name"))
        Next

    End Sub

End Module

Fill() retrieves the records and stores them in the DataSet. After the data has been loaded, the application can work with the DataSet without continuously communicating with the database.

ASP.NET Application Life Cycle

Definition

The ASP.NET Application Life Cycle is the sequence of events that occurs from the start of an ASP.NET application until the application is stopped or restarted. It describes how ASP.NET creates the application, initializes resources, processes requests, handles errors, and finally shuts down the application.

1. Application Start

The application starts when ASP.NET receives the first request for an application after it has been started or restarted. ASP.NET creates an instance of the application's HttpApplication class and initializes the application.

Application_Start

Occurs when the application starts. Generally used for application-wide initialization, such as:

  • Registering routes
  • Configuring application-level settings
  • Initializing application resources
  • Registering filters
  • Setting up other application-wide objects

Sub Application_Start(ByVal sender As Object,

Important Request Life Cycle Events

1. BeginRequest

The first event in the request-processing pipeline. Occurs when ASP.NET begins processing a request.

VB.NET
Sub Application_BeginRequest(
    ByVal sender As Object,
    ByVal e As EventArgs)

End Sub

Purpose: operations at the beginning of a request, logging, request preprocessing.

2. AuthenticateRequest

ASP.NET determines the identity of the user. Authentication answers: "Who are you?"

3. AuthorizeRequest

After authentication, ASP.NET determines whether the authenticated user has permission to access the requested resource. Authorization answers: "Are you allowed to access it?"

4. ResolveRequestCache

ASP.NET checks whether the requested response is already available in the cache. If a cached response exists, ASP.NET may use it instead of processing the request again — improving performance.

5. AcquireRequestState

ASP.NET obtains the state information associated with the request (session state, application state), allowing the application to access session-related information.

6. Execute Request Handler

ASP.NET identifies and executes the appropriate handler for the request. For a Web Forms application, this may involve processing an .aspx page, which is processed to generate the required response.

7. ReleaseRequestState

After request processing is completed, ASP.NET releases the request-related state — for example, session-related resources can be released or updated.

8. UpdateRequestCache

ASP.NET may update the cache with the generated response, depending on the application's caching configuration.

9. EndRequest

The final event in the request pipeline — occurs when ASP.NET has finished processing the request.

VB.NET
Sub Application_EndRequest(
    ByVal sender As Object,
    ByVal e As EventArgs)

End Sub

Can be used for logging, cleanup, and final request processing.

3. Application Running

After startup, the application can process many requests, remaining active until an event causes ASP.NET to restart or shut it down.

4. Application End

An ASP.NET application may terminate or restart because of events such as:

  • Application/server shutdown
  • Configuration changes
  • Application restart
  • Server restart
  • Changes to application files
  • IIS application pool recycling

When the application is shutting down, the Application_End event occurs.

VB.NET
Sub Application_End(
    ByVal sender As Object,
    ByVal e As EventArgs)

    'Cleanup code

End Sub

Application State

Shared by all users of the application.

Session State

Stores information for one particular user/session.

VB.NET
Session("UserName") = "Rahul"

Session vs Cookies

Definition of Session

A Session is a server-side mechanism used by ASP.NET to store and maintain user-specific information during a user's interaction with a web application.

VB.NET
Session("UserName") = "Rahul"

The data is stored on the server, while the browser normally holds only a session identifier.

Definition of Cookies

A Cookie is a small piece of data stored on the client's web browser. It is used to remember information about a user between requests.

VB.NET

Session stores user-specific application data primarily on the server, whereas a cookie stores small amounts of data in the user's web browser.

State Management in ASP.NET

Definition

State Management in ASP.NET is the technique used to maintain and preserve information between multiple requests made by a user or between different users. HTTP is a stateless protocol, meaning the web server does not automatically remember information from one request to the next. ASP.NET provides different state-management techniques to overcome this limitation.

Why State Management Is Required

Consider a login page: the server authenticates the user on Request 1, then the user opens their profile on Request 2 — since HTTP does not automatically remember previous requests, ASP.NET needs state management to know who the user is.

Types of State Management

Diagram

        STATE MANAGEMENT     STATE MANAGEMENT
              │                   │

       │      │      │      │     │        │
       ▼      ▼      ▼      ▼     ▼        ▼
    Cookies ViewState Query Session Application
             State    String   State   State

Client-Side State Management

State information is maintained on the client/browser side. Main techniques: ViewState, Cookies, Hidden Fields, Query String, Control State.

1. ViewState

ViewState is a Web Forms technique used to preserve the values of controls between postbacks. It is stored in a hidden field in the HTML page sent to the browser.

Diagram
       ASP.NET SERVER
             │
             │ ViewState
             ▼
       WEB BROWSER
             │
             │ Postback
             ▼
       ASP.NET SERVER
             │
             ▼
       Restore Control Values
VB.NET
ViewState("UserName") = "Rahul"

Dim name As String = ViewState("UserName").ToString()

Advantages: easy to use, automatically maintains control values, no server-side storage required.
Disadvantages: increases page size, not suitable for sensitive information, mainly tied to Web Forms.

2. Cookies

A small piece of information stored in the user's web browser.

VB.NET
Response.Cookies("UserName").Value = "Rahul"

Dim name As String =
    Request.Cookies("UserName").Value

Uses: user preferences, small identifiers, remembering settings.

3. Hidden Field

Stores data in a hidden HTML form field that is submitted along with the page.

ASPX + VB.NET
<asp:HiddenField
    ID="HiddenField1"
    runat="server" />

' VB.NET
HiddenField1.Value = "101"
Dim id As String = HiddenField1.Value

The user does not normally see the field on the rendered page, but its value is present in the HTML sent to the browser.

4. Query String

Passes information through the URL, e.g. Student.aspx?id=101&name=Rahul.

VB.NET
Dim id As String = Request.QueryString("id")

Advantages: simple, easy to implement, no server-side storage required.
Disadvantages: data is visible in the URL, limited amount of data, not suitable for sensitive information.

5. Control State

Control State preserves the essential state of an ASP.NET server control even when ViewState is disabled — useful for controls that require certain state information to function correctly.

Server-Side State Management

Information is maintained on the server. Main techniques: Session State, Application State, Cache.

1. Session State

Stores information associated with a particular user's session.

VB.NET
Session("UserName") = "Rahul"

Dim name As String =
    Session("UserName").ToString()

Uses: login information, shopping cart, user-specific preferences, temporary user data.

2. Application State

Stores information that is shared by all users of an ASP.NET application.

VB.NET
Application("CollegeName") =
    "Satyam College"

Dim name As String =
    Application("CollegeName").ToString()

Uses: website-wide settings, counters, global configuration information.

3. Cache

Caching stores frequently used data temporarily so it can be retrieved quickly without repeatedly performing expensive operations.

VB.NET

Uses: improving performance, reducing database requests, storing frequently accessed data.

Event-Driven Programming

Definition

Event-Driven Programming is a programming approach in which the flow of program execution is determined by events generated by the user, system, or application. An event is an action such as clicking a button, changing a value, loading a page, or submitting a form. When an event occurs, an associated event handler is executed. In ASP.NET Web Forms, event-driven programming is an important feature that allows developers to respond to user actions.

Basic Concept

Diagram
        USER / SYSTEM
              │
              │ Generates Event
              ▼
       ┌───────────────┐
       │     Event     │
       │ Button Click  │
       └───────┬───────┘
               │
               ▼
       ┌───────────────┐
       │ Event Handler │
       └───────┬───────┘
               │
               ▼
        Execute Code
               │
               ▼
            Output

Example: User clicks "Submit" → Button_Click event occurs → btnSubmit_Click() executes → "Submitted Successfully" displayed.

Important Terms

1. Event

An event is an action or occurrence that can trigger a response — e.g. Button Click, Page Load, Text Changed, Selected Index Changed, mouse/keyboard actions in applicable controls.

2. Event Handler

An event handler is a method that contains the code executed when an event occurs.

VB.NET
Protected Sub btnSubmit_Click(
    sender As Object,
    e As EventArgs)

    lblMessage.Text = "Submitted"

End Sub

Here: btnSubmit_Click → event handler, sender → object that generated the event, e → event information.

3. Event Source

The event source is the object/control that generates the event.

ASPX
<asp:Button
    ID="btnSubmit"
    runat="server"
    Text="Submit"
    OnClick="btnSubmit_Click" />

Here, btnSubmit is the event source.

Page_Load Event

Page_Load is one of the most commonly used ASP.NET page events.

VB.NET
Protected Sub Page_Load(
    sender As Object,
    e As EventArgs)

    If Not IsPostBack Then
        lblMessage.Text = "Welcome!"
    End If

End Sub

Why IsPostBack?

A Web Forms page can be requested initially and then submitted back to the server: on the first request IsPostBack = False; on a postback request IsPostBack = True. This is useful when initialization should happen only on the first page load.

Advantages of Event-Driven Programming

  • Interactive applications can be developed easily.
  • Responds directly to user actions.
  • Makes GUI/web applications easier to design.
  • Different events can have separate event handlers.
  • Promotes modular programming.
  • Makes applications more responsive to user interaction.
  • ASP.NET provides many built-in events.

Disadvantages

  • Large applications can have many event handlers.
  • Event flow can sometimes be difficult to understand.
  • Debugging complex event interactions can be challenging.
  • Incorrect event ordering can cause unexpected behavior.
Remember

Event = What happened?  |  Event Handler = What should the program do when it happens?  |  Event Source = Which control generated the event?

Exam Conclusion

Event-driven programming is a programming technique in which program execution is controlled by events. In ASP.NET Web Forms, controls such as Button, TextBox, DropDownList, and Page generate events, and event handlers written in VB.NET execute the required code when those events occur.
